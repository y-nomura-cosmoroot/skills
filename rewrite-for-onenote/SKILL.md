# 概要
カレントディレクトリの `from_notebooklm.md` を読み込み、2段階で処理して `to_onenote.md` へ書き出す。

# 手順

1. カレントディレクトリの `from_notebooklm.md` をReadツールで読み込む。ファイルが存在しない、または中身が空の場合はエラーを伝えて終了する。

2. 読み込んだ文章に対して `/rewrite-ai-tone` スキル（`rewrite-ai-tone/SKILL.md`）のルールを適用し、AI臭を除去したリライトを行う。この文章は会議の要約なので、発言者と決定事項を保つことを優先し、元文にない発言者や事実を足さない。最終的な出力先はOneNoteなので、元文にMarkdownがあっても引き継がず、プレーンテキストにする。

3. リライト結果に対して、下記の「OneNote整形ルール」を適用して書式を整える。

4. 書き出す前に、下記の「出力前チェック」を全項目満たすまで直す。

5. `to_onenote.md` が既に存在し中身がある場合、AskUserQuestionで「to_onenote.mdを上書きしますか？」と確認する。拒否された場合は処理を中止する。

6. 整形済みの文章を `to_onenote.md` にWriteツールで書き出す。

7. 完了を伝える。解説や補足は不要。

# OneNote整形ルール

OneNoteはプレーンテキストの改行をそのまま1行分の間隔として表示する。空行を入れると間隔が倍になるため、以下のルールで整形する。

## 改行
- 段落間に空行を入れない。単一改行で段落を区切る。
- セクション区切りの罫線の前だけ1行空ける。

## 見出し・構造
- 大見出し（セクション）は ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ で挟む。
- サブセクション見出しには先頭に ■ を付ける。
- 項目の列挙は 　・ （全角スペース＋中黒）で始め、説明文は 　　 （全角スペース2つ）でインデントする。
- 見出しは何を話したかを普通の語で書く。分析・評価・総括・洞察・統治・定点観測・チェックリストといった語は使わない。冒頭の大見出しには内容に即したタイトルを付ける（「エグゼクティブ・サマリー」のような汎用的な見出しにしない）。

## 口調
- 元文は議事録である。「誰が何をした」「何が決まった」「何がまだ決まっていない」が読み分けられる書き方にする。
- 決まったルール、ツールの機能、確認された事実は断定でよい（「メインブランチへの直接コミットを禁止し、PRを必須とする」「売上に対して原価が過少なプロジェクトを自動抽出するもの」）。
- 発言者が元文に書いてあれば人を主語にする（「〇〇さんから〜と提案があった」「〇〇さんが〜を調査する予定」）。書いてなければ発言者を作らず、「〜が提案された」「〜が確認された」「〜という話が出た」と動作で報告する。
- 文末に「〜との話」「〜との認識」「〜との指摘」「〜との意見」「〜との方針」「〜との見方」「〜との評価」を足して報告調にしない。元文の断定が強すぎるときは語尾ではなく動詞を直す（「決定された」→「開始しようとしている」、「即時実施する」→「提案された」「検討する」）。
- 「〜すべきだ」「〜は論外」のような社説調は、誰の意見か分かれば「〇〇さんは〜と話した」、分からなければ「〜のほうがいいという話が出た」にする。
- 「（担当：A・B）」の括弧は使わず、「Aさんが〜する」「AさんとBさんで〜する」と本文に組み込む。

## 句点と改行
- 一文一行。「。」で終わる文はそこで改行する。
- 一行に複数の文を詰め込まない。
- 行末の「。」は付けない。

## その他
- Markdown記法は一切使わない。
- 元文より長くしない。事実を落とさない限り短くなってよい。
- 敬称の「氏」は会議参加者だけ「さん」に置き換える。外部の人物（経営者・著名人など）は「氏」のまま。「〇〇・△△両氏」は「〇〇さんと△△さん」にほどく。

# 出力前チェック
- 行の途中に「。」がない（一文一行になっている）。
- 文末の「〜との話」「〜との認識」などの報告語尾が全体で3回以内。
- 見出しに 分析・評価・総括・洞察・統治・定点観測・チェックリスト がない。
- Markdown記号（`**`、`#`、`-` の箇条書き）、「： 」、「！」が0件。
- 元文の固有名詞・数字・人名がすべて残っている。
